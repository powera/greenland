About Sync Operations

Each category compares the release files with the database and lists the differences. For every difference you choose which side wins, or skip it. Long difference lists are paginated; the button under each list applies one choice to the whole list, including the rows not on the current page.

Common workflows:

  • Publishing database work: export or sync back to the release files. This is the direction the sync system is used in most of the time.
  • After editing release files by hand: import new entries and pull changed records into the database.
  • Building a database from scratch: use bootstrap_database.py rather than this UI - it imports the whole release tree in one pass, including lemma audio, idioms and names.
  • Quality assurance: review differences to catch inconsistencies before they ship.

Concepts are intentionally absent: they are keyed to Wikidata and are never exported. The only concept data in data/release is a lemma's Q-id, which the lemma sync reconciles.
