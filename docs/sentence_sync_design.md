# Sentence Release Sync - Design

This document describes the design for syncing sentences between
`data/release/sentences/` JSONL files and the SQLite database, mirroring the
existing lemma sync system in `src/barsukas/routes/sync_release.py`.

## GUID Format

Sentences use a `S_NNNNN` format (5-digit, zero-padded), matching the existing
wireword output convention used in `export_wireword_sentences.py`,
`export_wireword_conversations.py`, and `vieversys.py`.

The Sentence SQLAlchemy model currently has no `guid` column. A new nullable,
unique, indexed column must be added to the `sentences` table. Existing
sentences get backfilled with `S_{id:05d}`. New sentences can remain
`guid=NULL` until curated for release (same pattern as Lemma, where many
uncurated rows have `guid=NULL`).

The one existing outlier is `migrate.py:290` which uses `:06d` - that should
be updated to `:05d` for consistency.

## Release File Layout

Sentences are grouped by their **primary lemma** - defined as the noun (from
`sentence_pattern_words`) with the lowest GUID. This places sentence files
alongside the lemma files they teach:

```
data/release/
├── lemmas/
│   └── nouns/food/base.jsonl         (existing)
└── sentences/
    ├── nouns/
    │   ├── food/base.jsonl           sentences whose primary lemma is a food noun
    │   ├── animal/base.jsonl
    │   └── human/base.jsonl
    ├── verbs/
    │   └── physical_action/base.jsonl  fallback when no noun in pattern
    └── misc/
        └── base.jsonl                  no pattern_words or no resolvable lemma
```

### Primary Lemma Resolution

Given a sentence's `SentencePatternWord` records:

1. Collect all pattern words where `lemma_id` is not NULL
2. Join to `lemmas` to get each lemma's `guid`, `pos_type`, `pos_subtype`
3. Filter to nouns only (`pos_type = 'noun'`)
4. Pick the one with the lowest GUID (alphabetic sort, e.g. `N02_005` < `N06_001`)
5. If no nouns exist, fall back to any lemma with the lowest GUID
6. If no pattern words resolve to a lemma with a GUID, file goes to `misc/`

The resolved `pos_type` and `pos_subtype` determine the directory, using the
same pluralized directory names as lemmas (`noun` -> `nouns/`, etc.).

## JSONL Record Format

Each line in a sentence `base.jsonl`:

```json
{
  "guid": "S_00142",
  "pattern_type": "SVO",
  "tense": "present",
  "minimum_level": 3,
  "translations": {
    "en": "The dog eats bread.",
    "lt": "Šuo valgo duoną.",
    "zh": "狗吃面包。",
    "fr": "Le chien mange du pain."
  },
  "pattern_words": [
    {"position": 0, "slot_name": "subject", "lemma_guid": "N02_001", "english_text": "dog"},
    {"position": 1, "slot_name": "verb", "lemma_guid": "V01_003", "english_text": "eat"},
    {"position": 2, "slot_name": "object", "lemma_guid": "N06_001", "english_text": "bread"}
  ]
}
```

Fields:

| Field | Source | Notes |
|-------|--------|-------|
| `guid` | `sentences.guid` | `S_NNNNN` format, the sync key |
| `pattern_type` | `sentences.pattern_type` | e.g. "SVO", "SVAO"; nullable |
| `tense` | `sentences.tense` | e.g. "present", "past"; nullable |
| `minimum_level` | `sentences.minimum_level` | Analogous to lemma `difficulty_level` |
| `translations` | `sentence_translations` | All languages including English |
| `pattern_words` | `sentence_pattern_words` | Lemma GUIDs (not DB ids) for portability |
| `notes` | `sentences.notes` | Included only when non-empty |

### What is NOT in the release file

- **`SentenceWord` records** - per-language word breakdowns are generated by
  the translation agent and are runtime data, not curated content.
- **`verified` / `rejected`** - editorial workflow state, not release content.
- **`source_filename`** - the file path encodes the grouping; `source_filename`
  is an internal agent bookkeeping field.
- **Conversation sentences** - excluded entirely from the sentence release
  (filtered by checking `ConversationSentence` associations). Conversations
  get their own sync system later.

### File sorting

Records within each `base.jsonl` are sorted by GUID. Gaps are expected when
sentences are removed (same convention as lemma files).

## Sync Operations

Five sync modes, mirroring the lemma system:

### 1. Additions (release -> DB)

GUIDs present in release files but not in the `sentences` table.

Import action:
1. Create `Sentence` row with `guid`, `pattern_type`, `tense`, `minimum_level`
2. Create `SentenceTranslation` rows for each language in `translations`
3. For each `pattern_words` entry: resolve `lemma_guid` -> `lemma_id` via
   `Lemma.guid` lookup, create `SentencePatternWord`. If a lemma GUID doesn't
   exist in the DB, log a warning and skip that pattern word.
4. Log via `log_operation(source="sync-release", operation_type="sentence_import")`

### 2. Removals (DB -> delete)

GUIDs present in DB (non-NULL `sentences.guid`) but not in any release file.
Excludes conversation sentences (they're expected to have no release file).

Delete action cascades to `SentenceTranslation`, `SentenceWord`,
`SentencePatternWord` via SQLAlchemy cascade rules already defined on the model.

### 3. Level Changes

Same GUID, same English text (`translations.en`), different `minimum_level`.

Action: update DB `minimum_level` from release value.

This is analogous to the lemma difficulty sync.

### 4. English Text Changes

Same GUID, different English translation (`translations.en`).

Action: show side-by-side comparison; user picks release version or DB version.
The winning text updates the relevant `SentenceTranslation` row (if DB wins)
or the release file line (if release wins).

### 5. Translation Sync (bidirectional)

Same GUID, same English text, but different translations for non-English
languages.

Bidirectional actions (per language, per sentence):
- **use_release**: update `SentenceTranslation` row from release value
- **use_db**: rewrite the JSONL line in the release file with DB value

Same pattern as the lemma translation sync with `_apply_release_translation_updates()`.

## Conversation Sentence Exclusion

Both export and sync exclude any sentence that has a row in
`conversation_sentences`. The exclusion query:

```python
conversation_sentence_ids = set(
    row[0]
    for row in session.query(ConversationSentence.sentence_id).distinct().all()
)
```

This matches the existing pattern in `export_wireword_sentences.py:155-161`.

## Implementation Plan

### Schema Change

Add `guid` column to `Sentence` in `src/wordfreq/storage/models/schema.py`:

```python
guid: Mapped[Optional[str]] = mapped_column(
    String, unique=True, nullable=True, index=True
)
```

Backfill existing rows: `UPDATE sentences SET guid = 'S_' || printf('%05d', id)`

Fix `migrate.py:290` to use `:05d` instead of `:06d`.

### Export: `sqlite-to-sentence-release`

Add new migration direction in `migrate.py` (or a standalone script) that:

1. Queries all sentences with non-NULL `guid`, excluding conversation sentences
2. Eager-loads `translations` and `pattern_words` (with `pattern_words.lemma`)
3. Resolves primary lemma for directory placement
4. Groups by resolved (pos_type, pos_subtype)
5. Writes `data/release/sentences/{type}/{subtype}/base.jsonl`

## Open Questions

1. **Backfill scope**: Should all existing sentences get GUIDs, or only
   verified/non-rejected ones? Recommendation: all non-conversation sentences,
   since we can always remove them from release files later.

2. **Pattern word handling on import**: When importing a sentence from release
   that references a lemma GUID not yet in the database, should we block the
   import or allow it with a warning? Recommendation: allow import, skip
   unresolvable pattern_words with a flash warning.

3. **Sentence GUID assignment for new sentences**: Should the buivolas/zvirdlis
   agents auto-assign GUIDs when creating sentences, or should GUIDs only be
   assigned during export curation? Recommendation: assign during export, to
   match the lemma workflow where agents create rows and curation assigns GUIDs.
